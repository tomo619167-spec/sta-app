# Phase 4 集中タイマー

## 操作

下部ナビゲーションはホーム／タイマーです。テーマの「集中する」、項目詳細の補助リンクからも対象を設定して起動できます。学習ノートへの従来の経路は維持しています。

- シンプル：15・25・45分、自由設定は1〜180分。開始／一時停止／再開／終了。
- ポモドーロ：集中25分、短い休憩5分、長い休憩15分、4セットごとに長い休憩が初期値。時間は1〜180分、セット数は1〜12回に設定できます。
- モード・設定をIndexedDBに保存します。実行中・一時停止・途中終了確認中・休憩待ちの変更は禁止します。
- 対象は指定なし／科目／テーマ／項目。選択は任意です。別の対象のリンクから開いても、実行中の対象を上書きしません。
- 集中の満了時点で自動保存。途中終了は実績を確認して保存／今回のセットを破棄を選びます。完了済みのポモドーロセットは破棄しません。
- 集中後の休憩、休憩後の集中はいずれもボタン操作で開始します。休憩を集中時間へ加算しません。各セット後にアウトプットを強制せず、学習サイクルの終了後に既存の説明・理解を深める導線を表示します。

## 計測と保存

`lib/focus.ts`に型、時刻ベースの計算、状態遷移、時間集計を分離しました。`FocusProvider`はルートに置き、画面移動で破棄されません。インターバルは表示更新と満了検知にだけ使用します。実績は保存済みの経過ミリ秒と最後の開始時刻から求め、秒単位で保存します。一時停止中は加算しません。バックグラウンドから大幅に遅れて戻っても、1区間の実績は予定時間までです。休憩・次セットを自動で開始しないため、留守中のセット数が増えることもありません。

IndexedDB `yohaku-study`をv7へ更新します。v6の既存12ストアの行は書き換えず、以下の2ストアのみ追加します。失敗時はバージョン更新全体をロールバックします。

| ストア         | 内容                                                                                                                                                                             |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| focus-state    | 単一行`timer`。最後のモード・設定、revision、実行中タイマー、対象、開始時刻・停止までの経過時間、集中／休憩、セット数、保存後の状態                                              |
| focus-sessions | セッションID、モード、対象種別・ID、対象と親階層のID・名称のスナップショット、開始・終了日時、予定・実績秒数、完了／途中終了、ポモドーロのサイクルID・セット番号、作成・更新日時 |

状態遷移と集中記録の追加は同一のreadwriteトランザクションです。各集中区間に固定したセッションIDを使い、存在確認後に追加します。並行したタブ・満了・再読み込み・終了操作で同じ区間を重複保存しません。保存に失敗した場合、記録と状態をともに戻し、画面に再試行を表示します。BroadcastChannelで他タブへ変更を通知し、復帰時にも再読込します。revisionの古い読込結果で表示を巻き戻しません。

元の学習対象が削除されても、実行中状態と過去の集中記録は削除しません。関連学習へのリンクは現存する対象を検証して表示し、見つからない場合は項目を選ぶ導線へ戻します。集中記録自体を削除すると集計にも反映します。削除済み記録を完了状態から再作成しません。

## 学習ノート・集計

「すべて／説明／理解／集中」で即時に絞り込み、日付順に表示します。集中記録は既存のノート風アコーディオンへ追加し、同じ画面で予定・実績・セット等を確認・削除できます。テーマ・項目の最近の記録にも種別と時間を表示します。既存の本文・問い・AIフィードバックの閲覧、編集、削除は再利用しています。

`focusTotals`は今日・累計・科目・テーマ・項目の秒数を返します。項目の記録を親テーマ・科目へ、テーマの記録を親科目へ集計します。同じセッションIDは一度だけ数えます。帰属先は開始時の階層スナップショットです。今日の集計は端末のローカル日付で終了日を判定します（日付をまたぐ1セッションは終了日に計上）。複雑なグラフは追加していません。

## 制約・実機確認

- 完了音は初期オフ。ユーザー操作で音声コンテキストを有効にし、画面表示中に短い音を鳴らします。音声が利用できなくても計測・保存を続けます。
- OS通知・プッシュ通知は未実装です。バックグラウンドやスリープ中の即時通知・音は保証しません。復帰時に時刻から満了を検知し、保存・表示します。
- アプリが読み込み済みならオフラインでも計測・保存できます。サービスワーカーによる完全なオフライン起動・未読込の画面遷移は対象外です。
- 端末時計の手動変更やOSの時刻補正の影響は受けます。負の経過時間は加算せず、長時間の復帰は予定時間までに制限します。
- IndexedDBが消去された場合の復旧・クラウド同期は未実装です。
- 実機Android／iOSの長時間スリープ、ブラウザ強制終了後の復帰、音の再生、標準音声入力・ソフトキーボード、外部AI回答の品質は未検証です。

## 検証

単体テストは従来54件と集中機能14件。設定値・時刻計算・一時停止・途中終了・復元・並行操作・休憩・設定された長い休憩周期・破棄・保存失敗のロールバック・対象削除・集計・削除後の再作成防止・v6→v7移行と移行失敗後の再試行を含みます。

ブラウザテストは、集中機能5シナリオと既存33シナリオをモバイルChromium・モバイルWebKit・PC Chromiumで実行します。時間はブラウザのDateを進めて確認し、実時間のインターバルで満了を検知します。対象選択、終了後の学習導線、ノートの絞り込み・展開・削除、320px幅、オフラインと保存失敗の再試行も含みます。

結果：型チェック・本番ビルド・整形チェック、単体68件、E2E 114件が成功しました。削除確認の文言と完了音設定のタップ領域を調整した最終ビルドでも、シンプルタイマーの一連の操作と音設定の保存・復元を3環境で再検証し、3件すべて成功しました。WebKitの設定操作はPC用のクリックではなくスマホと同じラベルのタップで検証しています。OSの実キーボードや実際の音は検証していません。

起動は`npm install`、`npm run dev`。検証は`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`です。新しい依存パッケージ・外部API・認証・サーバーは追加していません。
