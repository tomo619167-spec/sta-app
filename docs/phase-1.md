# Phase 1 実装・検証記録

## 再開時に確認した状態

クラッシュ前のNext.js設定・依存導入・保存アダプター・ホーム・共通UI・テーマフォームが作業フォルダに残っていました。これらを再利用し、不足していたApp Routerのページ、テーマ詳細、記録・設定画面、スタイル、テストを追加しました。

指定先`https://github.com/tomo619167-spec/sta-app`は空のリポジトリでした。PRの比較元が必要なため、mainには短いREADMEだけの初期コミットを作成し、実装は`codex/phase-1-study-app`でレビューできるようにしています。別用途の`sumi-note`は変更していません。

## 完成した操作

- テーマ作成 → 詳細 → 編集 → 再読み込み後も保持
- 学習メモを追加 → テーマ詳細と記録画面に表示 → ホームの「最近の学び」に反映
- 5機能の予定ページへ移動し「現在は利用できません」を確認 → テーマへ戻る
- テーマ削除のキャンセル → 削除の確定 → 関連記録も削除 → 更新後も削除済み
- 必須・文字数制限、空状態、存在しないテーマ、保存不可時の再試行と入力維持

E2Eのスマホ設定はPlaywrightのiPhone 13プロファイル（viewportは390×664、touch・mobile設定、Chromium使用）です。実機Safariの検証を意味しません。

保存テストでは、新しい接続でのデータ読み出し、関連記録削除、他テーマの記録保護、不正入力拒否、削除済みテーマへの古い操作拒否、0%/50%の進捗計算、保存途中の失敗時に記録と日時が同時にロールバックされることを検証しました。

ブラウザテストでは、CRUD一連の操作、記録、更新後の保持、5機能の予定表示、下部ナビ、ダイアログのキャンセル・Escape、80文字のテーマ名での横はみ出し防止、IndexedDB拒否時の再試行表示、書き込み拒否時の入力維持を確認しました。最後の実行は10件すべて成功しています。

最初のブラウザテストでは、画面遷移待ちとNext.jsのルート通知用alertとの区別が不十分なテストセレクターを修正しました。再実行時はタイトルをh1で特定し、alertを対象フォーム・main内に限定しています。

## 実行環境上の対応

Node.js 24.22.1、npm 11.6.2、macOS上のインストール済みChromeを使用しました。環境にnpmコマンドがなかったため、作業用フォルダにnpm公式配布を取得し使用しました。この補助ツールはリポジトリに含みません。

Turbopackはこの実行環境のローカルポート作成制限によりビルドできなかったため、dev/buildの両方でNext.js標準のWebpackオプションを明示しています。
