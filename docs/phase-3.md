# Phase 3 — アウトプット・理解を深める

テーマ全体と学習項目の両方から同じ学習画面・入力コンポーネントを使います。現在の対象を明示し、本文を書く画面には正解・解説・AIの回答を表示しません。到達目標は必要なときだけ開きます。

## 学習の流れ

### アウトプット

「学習を記録」から記憶にあることを複数行で入力し、任意で4段階の完成度を選んで保存します。本文は30,000文字までです。保存ごとに新しい記録IDを発行し、学習日時・作成日時・更新日時を自動記録します。未評価の回は未評価のまま残し、以前の回の評価を引き継ぎません。

入力は標準のtextareaを使用します。独自の音声認識API・マイク権限・音声録音はありません。端末の標準キーボードの音声入力を利用できる構成で、入力中のキー操作や改行を独自に取り扱いません。実機での音声入力は未検証です。

完成度は既存の「まだ難しい・一部できた・概ねできた・十分できた」を再利用します。完成度、対象の習得度、AIフィードバックは独立し、自動更新や平均によるテーマ評価はありません。

### 理解を深める

「そもそも何？」「なぜ？」「どうやって？」「何が違う？」「何とつながる？」「もし〜だったら？」の6種類から選びます。テンプレートにテーマ名または項目名が入り、自分の問いを2,000文字まで編集できます。比較・関係・仮定の△△は自由に置き換えられます。

新規画面は「そもそも何？」のテンプレートから始まります。編集済みの文章があるときは、テンプレートで置き換えるか、文章を残して種類だけ変えるかを選べます。

「保存して外部AIへ」で、問いを保存してからプロンプトを開きます。同じ対象に複数の問いを保存でき、記録詳細から編集・削除できます。旧仕様で保存した仮説や気づきは、記録詳細の「以前の仮説・気づき」で読めます。

### 下書きと履歴

入力・評価変更のたびに下書きを保存します。対象種別、対象ID、活動種別で区別し、編集時は記録IDも含めた別の下書きにします。入力画面を閉じたりブラウザを開き直した場合は、同じ対象の「学習を記録」または同じ記録の「記録を編集」から復元できます。

下書きの保存中・保存済みを控えめに表示し、失敗時は現在の入力を画面に残して再試行を用意します。保存完了前の強制終了では最新の変更を失う場合があります。正式保存と該当下書きの削除は同じトランザクションで実行します。

履歴は日付順に表示し、一覧の長文を3行で省略します。「記録を開く」で全文と各回の完成度を確認し、編集・確認付き削除ができます。編集時も元の学習日時・作成日時を維持し、更新日時だけを更新します。同時編集で古い下書きから新しい記録を上書きしないよう版を照合し、競合時は下書きを保持したまま、明示的に最新の記録を読み込めます。

## 外部AIフィードバック

記録詳細の「外部AIでフィードバック」または「外部AIに相談」から、コピー → 外部AIで生成 → 結果を貼り付ける → プレビュー → 保存を同じダイアログ内で進めます。コピー成功を表示しても自動遷移しません。クリップボードが拒否された場合も、手動選択・コピー後に貼り付け画面へ進めます。外部サービスのアカウント連携・AI API・自動送信はありません。

出力評価のプロンプトには科目、テーマ、該当する学習項目、到達目標、本文を含めます。正確性、正しく説明した点、不足事項、誤解の可能性、具体的な助言、次の問い1〜3個、不確実性の明示を依頼します。深掘りでは問いの本文から説明・具体例・比較・追加質問・誤解しやすい点を依頼します。「そもそも何？」では定義・本質・具体例を中心にします。

AIの入力途中のステップ・プロンプト・コピー完了状態・JSONは記録IDごとの下書きとして保存し、外部AI利用から戻った際や再読み込み後も復元します。記録自体が編集された場合は再生成を求め、古い版へのJSONを現在の記録へ取り込みません。

## JSONの形式

プロンプトの形式例と受け入れる形式は、同じ`feedbackExample`と`parseFeedbackJSON`で管理します。Phase 2と共通のJSON構文・オブジェクト・必須文字列・未知キーの検証、貼り付けコンポーネント、全画面エディターを再利用します。

アウトプットの例：

```json
{
  "version": 1,
  "kind": "output",
  "recordId": "record-output",
  "targetType": "item",
  "targetId": "item-cause",
  "revision": "2026-11-08T12:00:00.000Z",
  "questions": ["税制と身分制度の関係をどう説明しますか？"],
  "uncertainty": ["資料がないため細部の時期は確認できません"],
  "strengths": ["因果関係を整理できています"],
  "missing": ["異なる身分の視点も検討できます"],
  "misunderstandings": [],
  "advice": ["原因と結果を分けて説明してみましょう"]
}
```

理解を深める場合の例：

```json
{
  "version": 2,
  "kind": "deepen",
  "recordId": "record-deepen",
  "targetType": "theme",
  "targetId": "theme-revolution",
  "revision": "2026-11-08T12:00:00.000Z",
  "questions": ["税制の違いはどの身分に影響しましたか？"],
  "uncertainty": [],
  "explanation": "税負担の偏りは当時の財政や身分制度と関係します。",
  "examples": ["免税特権の有無で負担が異なる場合があります。"],
  "comparisons": ["同じ税制でも、身分ごとに制度上の扱いが異なりました。"],
  "misunderstandings": [
    "財政難と革命の原因を一つに結び付けすぎないようにします。"
  ]
}
```

実際の識別情報はアプリが生成するプロンプトの値をそのまま使用します。例の各キーはすべて必須で、指定外のキーは拒否します。アウトプットはversion 1、理解を深める機能はversion 2を生成します。既存の深掘り用version 1も取り込めます。kind・記録ID・対象種別・対象ID・revisionを取り込み先と照合します。

questionsは1〜3件、他の配列は0〜12件です。各要素は空でない2,000文字以内の文字列、explanation（旧形式ではassessment）は5,000文字以内、JSON全体は100,000文字以内です。構文・型・必須項目・件数・上限・取り込み対象・版の不一致を具体的なエラーとして示します。Markdownのコードブロックは受け付けません。

プレビューでは保存せず、確認後の登録直前にも検証します。保存失敗は全体をロールバックし、下書き・既存記録・既存フィードバックを維持します。AIの内容はReactの文字列として描画し、信頼済みHTMLとして扱いません。

## 保存構造と移行

IndexedDB `yohaku-study`をv6へ加算的に移行します。v5の既存9ストアは書き換えず、次の3ストアだけを追加します。古い記録に新しい評価・日時・問いを自動生成しません。旧％評価、原本退避、手動科目アイコン、習得履歴、Phase 2の途中のロードマップドラフトも維持します。

| ストア                    | 内容                                                                                                            |
| ------------------------- | --------------------------------------------------------------------------------------------------------------- |
| records（既存）           | OutputRecord / DeepeningRecord / 旧学習メモ。対象種別・ID、本文、完成度、日時、問い。旧記録の仮説・気づきも保持 |
| learning-drafts（新規）   | OutputDraft / DeepeningDraft。活動・対象・編集する記録で区別、version 1                                         |
| learning-feedback（新規） | OutputFeedback / DeepeningFeedback。対象・記録ID、登録日時、検証済みJSON、元の本文と版のスナップショット        |
| feedback-drafts（新規）   | 外部AIとの作業途中。記録IDで区別、version 1                                                                     |

AIフィードバックは記録の編集後も保持し、編集前の本文への参考情報であることを明示します。ユーザーの完成度や習得履歴は更新しません。正式保存・フィードバック登録と対応する下書き削除は、それぞれ同一トランザクションです。

記録削除では紐付くフィードバックとその記録の編集中の下書きを削除し、同じ対象の新規入力ドラフトは維持します。項目・テーマ削除では、その対象のドラフトとフィードバックも既存の削除トランザクションに含めます。別の項目・テーマのデータには触れません。

## 学習記録との連携

「記録」画面では、アウトプット、理解を深める記録、AIフィードバックを日付順に並べます。科目・テーマ・項目・対象種別・記録の種類で絞り込めます。ロードマップの展開した項目に「この項目の記録」を設け、項目で絞り込んだ記録へ移動できます。
