# Phase 4.5 鉛筆と集中ノート

## 表示

「集中した時間が、ノートに刻まれていく」を、控えめな紙・罫線・オリーブ色の手描きSVGで表現します。実際の文章や円形ゲージは生成しません。短い線、曲線、囲み、丸、矢印を組み合わせた4種類のパターン（connections／ideas／discovery／perspectives）を用意しました。

タイマー画面はモード → ノート → 残り時間 → 状態 → 設定・セット表示 → 対象 → 操作の順です。ノートは高さ126〜176pxで幅に合わせて縮小します。既存の余白と残り時間のサイズを調整し、紙・鉛筆・図形が狭い画面からはみ出さない表示領域を確保しました。完了後も描いたページと小さなチェックを表示し、従来の学習アクションへつなぎます。

## 状態の再構成

描画は表示専用です。`lib/focus.ts`、保存アダプター、`FocusProvider`、IndexedDB v7の構造・既存レコードは変更しません。新しい描画履歴や設定も保存しません。

`notebookPage`は既存の`focusElapsed`と予定ミリ秒から進捗を算出し、0〜1に制限します。パターンは保存済みの`timerId`＋セット番号を固定シードにしたハッシュで選ぶため、同じページを再読み込みしても配置は変わりません。

- 開始前はほぼ白紙、鉛筆は最初の線の始点。
- 集中中は現在の経過時刻に対応する位置まで描画。
- 一時停止・途中終了は保存された経過時間の位置で停止。保存・破棄後の画面にも途中のページを残します。
- 満了時は全ストロークと小さなチェックを表示。
- ポモドーロの休憩は直前の集中セットのページを固定表示。休憩時間を進捗に含めません。次の集中でページIDと図形を切り替えます。補助表示はSET番号です。

## 描画方式・分割

| ファイル                     | 役割                                                                   |
| ---------------------------- | ---------------------------------------------------------------------- |
| lib/focus-notebook.ts        | タイマーからの表示状態、決定的ハッシュ、ストロークの時間配分・位置計算 |
| focus-notebook-animation.tsx | ノート全体、可視性・省モーションへの対応とフレーム管理                 |
| drawing-pattern.tsx          | 4種類の順序付きSVGパス                                                 |
| pencil-illustration.tsx      | ローカル座標(0,0)を先端にした小さなSVG鉛筆                             |
| drawing-progress.ts          | SVG DOMへ線の出現量と鉛筆位置を反映する表示専用レンダラー              |

パスの実長を初期化時に測り、長さに比例して描画時間を配分します。線の間には短い持ち上げ区間を設けます。描画中は`pathLength=1`と`stroke-dashoffset`で出現量を制御し、同じ進捗の`getPointAtLength`で求めた点へ鉛筆の原点を移します。持ち上げ区間は次の線の始点へ薄く移動し、インクは増やしません。

requestAnimationFrame内は最大約30回/秒のDOM更新だけで、Reactの毎フレームのstate更新は行いません。変更したストロークだけを更新し、形状・長さはキャッシュします。進捗は毎回現在時刻と既存の計測状態から求め、フレーム数や前フレームからの差分を集中時間に加算しません。

バックグラウンド・画面外では連続描画を止め、復帰時に現在の進捗を直接反映します。`prefers-reduced-motion`時は鉛筆を定位置に置き、既存タイマーの表示更新に合わせた静的な線の進捗だけを示します。設定を途中で切り替えても再読込は不要です。

SVGのパス計測が使えない場合は鉛筆を隠し、線の簡易表示へフォールバックします。計測・記録・操作はSVG APIに依存しません。演出全体を`aria-hidden`とし、残り時間と状態の既存テキストを維持しています。外部API・画像・依存ライブラリの追加はありません。

## 検証と制約

単体テストは既存68件に表示状態の6件を追加しました。すべてのシンプル設定時間での進捗、時間満了、一時停止・再開・途中終了、休憩と新セット、再読込後の同一ページ、時間配分・持ち上げ区間の座標計算を含みます。

新しいE2E 7シナリオを、モバイルChromium／モバイルWebKit／PC Chromiumで実行します。座標と線の出現量、再読込、部分ページ、完了記録の重複防止、省モーションの実行中切り替え、非表示・画面外での停止と復帰、SVG計測APIの故障、320px幅、4パターンの全描画経路で鉛筆が領域内に収まること、表示フレーム間での線の更新を検証します。既存のタイマー・学習・JSON・移行・保存の回帰テストも実行します。

実機Android／iOSでの長時間の電池消費・発熱・フレームレート、OSの実際のスリープ・強制終了は未検証です。ブラウザが停止中に描画フレームを保証することはできませんが、復帰時に現在の時刻へ追いつきます。短い持ち上げ区間では鉛筆が紙から離れて移動するため、その間の先端はインクの末尾とは一致しません。線を描く区間では先端を一致させています。

結果：型チェック・本番ビルド・整形チェック、単体74件、E2E 135件（45シナリオ×3環境）が成功しました。省モーション設定の連続切り替えも各環境3回、計9回成功。残り時間と描画進捗の一致を明示した最終確認も3環境で成功しました。開始前・集中中・途中終了・完了のスマホ画像を確認しています。

起動は`npm install`、`npm run dev`。検証は`npm run typecheck`、`npm test`、`npm run build`、`npm run test:e2e`です。
