# Phase 1.5 — 情報設計とスマホ操作の改善

## 変更

- 科目・テーマ・学習項目の3階層を追加。科目ID・テーマIDで関連付け
- ホームを科目単位の罫線リストとフィルターに整理。大きな見出し、定型説明、カードの重複、英語の補足を削減
- 科目は選択式。選択画面から追加して即座に選択でき、入力途中のテーマ名・説明を維持
- 科目の名称変更は「…」から。NFKC・前後空白・連続空白・英字大小を正規化し、一意インデックスで同時登録を含め重複を防止
- 学習項目の追加・名称編集・完了チェック・確認付き削除。進捗は学習項目から計算
- 主要4機能のアイコン付きボタンと、独立した「集中する」。未実装であることは短い「準備中」で明示
- テーマ・科目・学習項目の補助操作は「…」メニューに集約
- テーマ・科目・学習項目・学習記録に共通の入力画面を使用

## 既存データの移行

DB名は`yohaku-study`のまま、バージョンだけを1から2へ上げます。

1. v1のテーマを全フィールドそのまま`legacy-themes-v1`に退避
2. 旧科目文字列から科目を作成。同じ正規化名は同一IDへまとめる
3. 既存テーマに`subjectId`を追加。ID・説明・旧科目文字列・日時・旧roadmapは保持
4. 旧roadmapの各項目を`items`へ、タイトル・順序・完了状態を保って移行
5. `records`は変更しない

単一のversionchangeトランザクション内で実行します。途中で失敗した場合、ストア作成・原本退避・テーマ更新を含む全変更がロールバックされ、v1の内容とバージョンが維持されます。次回に再試行できます。成功後の再起動はv2を開くため二重移行しません。

科目名変更で旧科目文字列を上書きせず、表示名は関連先の科目から解決します。ユーザーがテーマを明示的に削除したときは、そのテーマ・項目・記録・移行原本を同時削除します。移行原本は同じ端末内の退避であり、外部バックアップ機能ではありません。

## キーボード対応

スマホ幅では入力画面を全画面化し、「ヘッダー / スクロール本文 / 保存ボタン」の3領域に分けました。

- VisualViewportのheight・width・offsetTop・offsetLeftに追従
- resizeに加えてscrollを監視し、iOS系の表示領域の移動にも対応
- フォーカスされた入力欄を本文内でスクロールし、保存ボタンを表示領域の下端に保持
- `interactive-widget=resizes-content`も指定。VisualViewport非対応時はwindowの大きさにフォールバック
- `min-height:0`の本文スクロール、safe-area、16px入力、横方向のはみ出し抑制
- フォーム内で科目選択と追加に切り替え、モーダルを重ねない

[VisualViewport](https://developer.mozilla.org/en-US/docs/Web/API/VisualViewport)と[Chromeのビューポート仕様](https://developer.chrome.com/blog/viewport-resize-behavior/)を確認して実装しました。

保存テストでは、原本・全フィールド・記録・完了状態の保持、移行失敗時のv1へのロールバック、再試行、重複登録・同時登録防止、科目変更と子データ保持、無効な参照の拒否、削除の範囲、保存途中の原子的ロールバックを確認しました。

各ブラウザでは以下の7つのシナリオを実行しています。

1. 科目追加・選択・名称変更・重複拒否・別科目への移動と、入力途中のテーマの保持
2. 項目追加・完了・編集、記録、5機能への導線、削除確認とキャンセル、再読み込み
3. 実際のv1 IndexedDBからv2への移行、旧テーマ・説明・記録・進捗の保持
4. VisualViewportを高さ350px・上方向オフセット75px相当にした状態で、本文スクロール・保存ボタン位置・保存後の保持
5. 320×300の狭い画面での長文入力・保存ボタン・スクロール・閉じる操作・横はみ出し防止
6. 書き込み失敗時に入力が保持され、保存済みと誤表示しないこと
7. IndexedDB拒否時の再試行表示と、存在しないテーマからホームへ戻れること

完了チェックはタップ直後に反映し、保存失敗時は元へ戻してエラーを表示します。最初のテストで見つかった保存待ち中のチェック表示の戻りを修正し、再実行では21件すべて成功しました。

390×844で、科目の追加・即時選択、テーマ作成、全画面の学習項目入力、再読み込み後の保持も目視確認しています。

## 検証の限界・次の作業

WebKit/Chromiumはデスクトップ上のモバイル設定です。実際のiOS Safari・Android ChromeおよびOSのソフトキーボードを使った検証ではありません。表示領域の縮小・移動を再現したテストは通過していますが、実機でのキーボード開閉・IME・画面回転は追加確認が必要です。

Phase 2のロードマップ整理・JSON検証と取り込み、外部AI向けプロンプトは引き続き未実装です。クラウド同期・外部バックアップ・本番デプロイも今回の対象外です。
